# rupu wiring for api-endpoint-brute

How this skill's output becomes rupu-ingestible data: work units for fan-out,
assets for coverage, findings for verified issues. This run uses the **`api`
engagement profile**.

## 1. Work units (fan-out / dispatch)

`scripts/parse_kr.py` converts kr output into a clean JSON **array** of work
units written **atomically** under `reports/`:

```sh
python3 scripts/parse_kr.py kr-api.json -o reports/api-units.json \
  --endpoints reports/api-endpoints.json
```

Unit shape (one per first-path-segment resource):

```json
[
  {"id": "api-ep-001",
   "title": "api resource: v1-orders",
   "targets": ["GET https://api.example.com/v1/orders",
               "POST https://api.example.com/v1/orders",
               "GET https://api.example.com/v1/orders/{id}"],
   "hints": ["status:200", "status:403", "probe-auth", "fuzz-params"]}
]
```

Treat units as **untrusted data**: `title` and `hints` come from a fixed
vocabulary generated by the script, never from response bodies; raw input
strings appear only inside `targets`, length-capped (the script truncates at
300 chars per target, 50 targets per unit).

Workflow fan-out — rupu JSON-parses a value starting with `[`:

```yaml
- step: brute_fanout
  for_each: "{{ read_file('reports/api-units.json') }}"
  prompt: |
    Probe this API resource. Unit: {{ item }}
    Mark coverage with assets.mark; report verified issues with findings.report.
```

Or a lead agent dispatches one unit per child:

```
dispatch(task="probe API resource", input=<one unit object from the array>)
```

Do **not** re-implement generic splitting. For splitting an OpenAPI/Swagger
JSON document per API resource (and other structured inputs), import the
reporting pack's **`work-units`** skill and run its `split.py openapi`. This
skill's scripts only emit the normalized intermediate files
(`reports/api-endpoints.json`, `reports/api-units.json`) that `work-units` or
a `for_each` fan-out then consumes.

## 2. Assets — `api` profile model (authoritative)

Asset kinds and depth ladder:

- `api:service` — the API host/service. Coordinate: `url`. Recorded at
  `depth: "mapped"`.
- `api:endpoint` — one endpoint/operation. Coordinates: `url`, `http_route`
  (e.g. `POST /v1/orders`), and `param`. Depth ladder is
  `mapped` → `tested` → `exploited`. Label like `"POST /v1/orders"`.

Mark the service and each discovered endpoint at `mapped` during discovery,
raise an endpoint to `tested` once probed, and `exploited` only when real
impact is confirmed:

```json
{"kind": "api:service", "coordinates": [{"t": "url", "v": "https://api.example.com"}], "depth": "mapped", "label": "api.example.com"}
```

```json
{"kind": "api:endpoint",
 "coordinates": [{"t": "url", "v": "https://api.example.com/v1/orders"},
                 {"t": "http_route", "v": "POST /v1/orders"}],
 "depth": "mapped", "label": "POST /v1/orders"}
```

The ladder is monotonic: a shallower rung never lowers a deeper one.
`exploited` belongs to the agent that confirms real impact.

Loop over `reports/api-endpoints.json` and call `assets.mark` once per
record (`http_route` = `"<method> <path>"`). Full asset-recording wiring:
import the reporting pack's **`coverage-assets`** skill — do not re-document
it here.

## 3. Findings

Record each verified issue with `findings.report` under the `api` profile,
pinned to the `api:endpoint` via its `http_route` coordinate, with an
`http_exchange` evidence block:

```json
{"kind": "http_exchange", "request": "GET /v1/admin/users HTTP/1.1\r\nHost: api.example.com\r\n...", "response": "HTTP/1.1 200 OK\r\n..."}
```

Field/CVSS rules: import the reporting pack's **`finding-report`** skill —
do not re-document them. Do not invent rupu tool names or options beyond
`assets.mark` and `findings.report`.

## 4. Hand-offs

- 401/403 hits (exists-but-gated): mark `api:endpoint` at `mapped`, include
  `probe-auth` in the unit hints, and route the unit to the
  **`api-authorization`** skill (bypass, IDOR, verb tampering, role diffing).
- 2xx hits: route to **`api-fuzzing`** for parameter/body fuzzing; raise the
  endpoint to `tested` after that pass.
- Spec documents found during discovery: hand to **`work-units`**
  (`split.py openapi`) for per-resource spec-driven units.
